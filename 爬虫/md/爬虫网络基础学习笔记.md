## 一、优先级：哪些内容该学、学到什么程度

爬虫工作的本质是"写程序当 HTTP 客户端"。以下按对爬虫岗位的重要程度排序：

| 资料 | 优先级 | 理由（爬虫视角） |
|---|---|---|
| **HTTP协议入门** | ⭐⭐⭐⭐⭐ 必须吃透 | 爬虫就是 HTTP 客户端。请求/响应结构、方法、状态码、Header、Cookie——面试必考、工作天天用 |
| **HTTPS 的七个误解** | ⭐⭐⭐⭐ 必须了解 | 绝大多数网站是 HTTPS。证书验证、SSL 报错、`verify=False`，爬虫几乎天天碰到 |
| **互联网协议入门（一）（二）** | ⭐⭐⭐ 掌握大框架 | 重点看 TCP/端口/DNS/分层思想；以太网、MAC、ARP、DHCP 浏览即可 |
| **SSL/TLS 协议** | ⭐⭐⭐ 了解握手流程 | 理解 HTTPS 为什么安全、TLS 握手怎么走，不用背细节 |
| **SSL 延迟有多大 / HTTPS 升级指南** | ⭐ 可跳过 | 写给网站运维/站长看，不是给爬虫工程师的，面试几乎不会问 |

### 时间分配策略

- 70% 时间给 **HTTP**（这是饭碗）
- 20% 时间给 **HTTPS/SSL**（要爬的网站基本都是 https://）
- 10% 时间给 **TCP/IP/DNS 框架**（懂原理、能解释"为什么断线/超时"就行）
- 运维向两篇看一眼结论即可

## 二、HTTP 篇：爬虫最核心的知识

### 2.1 HTTP 是什么

**HTTP 规定了"客户端请求 → 服务器响应"的对话格式**。爬虫里你就是那个客户端，`requests.get()` 就是你的嘴巴。

### 2.2 一次请求包含什么

`requests` 库在你背后干的事：

```http
GET /index.html HTTP/1.1              ← 方法 + 路径 + 版本
Host: www.example.com                   ← 要访问哪个网站
User-Agent: Mozilla/5.0 ...            ← 你是谁（爬虫伪装的重点！）
Accept: */*                            ← 你能接受什么格式
Accept-Encoding: gzip, deflate         ← 你能解压什么压缩
Cookie: session=abc123                 ← 你的"登录状态"
Connection: keep-alive                 ← 让连接复用

(空行)
POST 时这里才是请求体，GET 没有
```

### 2.3 关键概念逐个讲（爬虫直接对应）

#### 方法（Method）
- `GET`：拿数据（网页、JSON）。参数在 URL 里（`?key=value`）。
- `POST`：提交数据（登录、搜索、翻页）。参数在请求体里。
- 爬虫 90% 用这两个。面试常问："什么时候用 GET 什么时候用 POST？"

#### 状态码
| 状态码 | 含义 | 爬虫中的意义 |
| --- | --- | --- |
| 200 | 成功 | 正常拿到数据 |
| 301/302 | 重定向 | `requests` 默认自动跟随，**注意登录跳转陷阱** |
| 403 | 拒绝访问 | **最常见**——被反爬识别，补 UA/Referer/Cookie |
| 404 | 页面不存在 | URL 拼错或资源下线 |
| 429 | 请求太频繁 | **被限速**，要加延时 |
| 500 | 服务器出错 | 服务器问题，可稍后重试 |

#### Header 头信息（反爬的"正面战场"）
- `User-Agent`：很多服务器靠它判断"你是不是浏览器"。不设置有些站直接 403。
- `Referer`：告诉服务器从哪个页面跳过来，防盗链/反爬靠它。
- `Cookie`：登录凭证 + 会话状态。`requests.Session()` 自动保存和发送，**爬带登录的站必用**。

#### Content-Type / MIME type
告诉双方数据是什么格式：
- `application/json` → 直接 `.json()` 解析
- `text/html` → 用 BeautifulSoup / lxml 解析
- `charset=utf-8` → 中文乱码 90% 是编码问题

#### Content-Encoding: gzip
服务器压缩后再发。`requests` 自动解压，但要知道"为什么响应头有 gzip 字段"——不然抓包看到乱码会懵。

#### 无状态 + Cookie
HTTP 本身不记人，服务器靠 Cookie 记住你"登录过"。**爬虫要保持登录，必须用 `Session` 管理 Cookie**，而不是每次裸请求。

### 2.4 HTTP/1.1 连接复用对爬虫的影响

`Connection: keep-alive` 意味着多个请求可共用一个 TCP 连接。`requests.Session()` 用连接池复用了这一点——爬大量页面时用 Session 比每次新建连接快很多。这就是教程总让你用 `session = requests.Session()` 的原因。

### 2.5 HTTP/2 部分

爬虫只需要**知道它存在**。`requests` 默认不支持 HTTP/2（要用 httpx），但绝大多数网站 HTTP/1.1 就够了。面试能说出"HTTP/2 是二进制协议、支持多工、复用连接、避免队头堵塞"即可。

## 三、互联网协议篇：请求怎么到达服务器

### 3.1 五层模型

自下而上：实体层 → 链接层 → 网络层 → 传输层 → 应用层。每层各司其职，上层把数据塞进下层的数据里（封装）。

### 3.2 分层是怎么叠的

一次网页请求，数据一层层包起来：

```
应用层  HTTP    "GET / HTTP/1.1 ..."        ← 你的网页请求
传输层  TCP     包上端口号（目标80，随机源端口）  ← 可靠送达、分段
网络层  IP      包上 IP 地址（你 → 服务器）      ← 找到主机
链接层  以太网   包上 MAC 地址（你 → 网关）       ← 物理传输
```

服务器收到后反向一层层剥开，最后拿到 HTTP 请求（对应 `互联网协议入门（二）` 的 Google 例子）。

### 3.3 对爬虫真正有用的几个点

- **DNS（域名 → IP）**：`requests.get("https://www.baidu.com")` 第一步是把域名解析成 IP。报 `[Errno -2] Name or service not known` 时往往就是这一步出问题。**DNS 报错 ≠ 代码 bug**，可能是网络问题或 DNS 污染。
- **端口（Port）**：HTTP 默认 80，HTTPS 默认 443。报 `Connection refused` 通常是端口不对或服务没开。
- **TCP 的可靠性**：TCP 有确认机制，丢包重发，保证数据完整。爬虫收到的数据一定是完整的。"数据断了"更多是服务器主动断连（反爬）或超时设置太短。
- **IP / 子网掩码 / 网关**：网络工程师的活，爬虫只需要知道"你的电脑通过网关出去，服务器通过 IP 找到你"。

## 四、HTTPS / SSL 篇

### 4.1 HTTPS 是什么

**HTTPS = HTTP + TLS（加密层）**。HTTP 是明文，抓包能看到密码、Cookie；HTTPS 把内容加密，抓包只能看到密文。所以大站全是 HTTPS。

### 4.2 TLS 握手在干什么

浏览器访问 https 站点，正式传数据前先握手：

1. 客户端打招呼："我要连你，支持这些加密算法"
2. 服务器回："用这套算法，这是我的**证书**"
3. 客户端**验证证书**（CA 是否受信任？域名对不对？过期没有？）
4. 双方各自算出同一个"会话密钥"（**非对称加密**保证安全传输，**对称加密**保证速度）
5. 之后所有数据都用这个密钥加密传输

### 4.3 对爬虫意味着什么（三个高频场景）

- **`SSLError: CERTIFICATE_VERIFY_FAILED`** —— 证书验证失败。原因：抓包的站点证书不被信任、本地缺 CA 根证书、自签名证书。
  解决：`requests.get(url, verify=False)` 跳过验证，并 `urllib3.disable_warnings()` 屏蔽警告。**注意**：生产环境 `verify=False` 有被中间人攻击的风险，只在抓测试数据时用。
- **证书过期 / 配置错误** → 一样报 SSL 错误，不是代码问题，换个站测试。
- **HTTPS 代理**：公司/学校网络常用，`proxies={"https": "http://user:pass@proxy:port"}` 配置不对也会报 SSL 错。

### 4.4 "七个误解"里最该记住的几条

- ❌ "HTTPS = 完全加密，抓包什么都看不到" → **不是**。抓包工具能看到域名、IP、端口、数据大小，只是看不到内容正文。爬虫抓包分析照样能做。
- ❌ "证书有效 = 网站安全" → **不是**。证书只证明"这个域名是这个组织的"，不代表内容没毒。钓鱼网站也有合法证书。
- ❌ "HTTPS 防得了所有攻击" → **不是**。XSS、SQL 注入、DNS 劫持照样可能发生。
- ✅ **HTTPS 保护的是"传输过程"的机密性和完整性**，防的是"数据在中间被人偷看/篡改"。

### 4.5 SSL 延迟那两篇（背结论即可）

"TLS 握手会多几个 RTT（网络往返），但对现代网络**延迟增加很小（通常几十毫秒）**，为了安全完全值得。"升级指南是教站长把网站迁到 HTTPS 的操作文档，**现在不用学**。

## 五、给 50 天基础、冲 12 月爬虫岗的路线建议

1. **先把 `HTTP协议入门.md` 吃透** —— 对着 `requests` 库亲手发请求，看 `resp.status_code`、`resp.headers`、`resp.text` 对应文章的哪个概念。写脚本抓豆瓣/微博热搜练手，把 Header、Cookie、Session 都用起来。
2. **学 HTTPS/SSL 基本概念** —— 写几个访问 https 站点的脚本，故意不设 UA 看 403，故意 `verify=False` 看报错，体会反爬和证书。
3. **互联网协议篇当"故事书"读一遍** —— 懂分层、懂 DNS/TCP/端口，能解释"为什么会超时/断连"即可，别陷进 MAC、ARP 的细节。
4. **运维向两篇直接跳过**，等真需要再回来看。

### 面试能说出的三句话

1. "HTTP 是无状态协议，靠 Cookie 维持会话。"
2. "爬虫遇到 403 通常要伪装 User-Agent 和 Referer。"
3. "HTTPS 是 HTTP 加了一层 TLS 加密，保护传输过程的机密性和完整性。"
