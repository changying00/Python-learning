第 1 章  A Python Q&A Session
     Python 问答入门
归属：Part I  入门 Getting Started
级别：必读·轻松    优先级：中
========================================================================

【我的理解与总结】（加深）
用问答建立 Python 全景：为何用、谁在用、能做什么、何时不用。
这是「选型与预期」章，不是语法章。先建立合理预期：Python 强在生产力、
    生态与可读性，弱在极致原生算力。

【扩展理解】
• 六大理由口诀：质量、效率、移植、库、集成、乐趣。
• 典型战场：数据/AI、Web、自动化、测试、胶水集成、科学计算。
• 实现族：CPython（主流）、PyPy（JIT）、Jython/IronPython（平台桥）、
  MicroPython（嵌入式）。
• 「够快」策略：先正确再 profile；热点用算法、C 扩展、
  Cython/Numba或改写。
• 与其它语言：脚本与业务层 Python，内核/驱动/硬实时常 C/C++/Rust。

【踩坑点】
• 未测量就断言「Python 太慢」而过早优化或换语言。
• 把「能做」当成「最适合做」：嵌入式硬实时、超重 CPU 内核需谨慎。
• 公司名单会过时，抓住「通用脚本 + 胶水 + 生态」角色即可。
• 忽视乐趣与团队效率：长期维护与招聘成本也是选型的一部分。

【对你的帮助】
建立学习动机与合理预期，避免盲目跟风。

【建议掌握程度】
掌握约 70%：能说出主要理由、应用领域与性能短板。

第 2 章  How Python Runs Programs
     Python 如何运行程序
归属：Part I  入门 Getting Started
级别：必读·基础    优先级：高
========================================================================

【我的理解与总结】（加深）
执行链：源码 .py →（编译）字节码 .pyc → PVM 解释执行 → 最终落到机器码。
CPython 是标准参考实现；替代实现可换 VM 或加 JIT/AOT。
    懂这条链才能理解性能、.pyc 与部署。

【扩展理解】
• 编译多在 import/加载时自动发生，对开发者透明。
• __pycache__ 中的 .pyc 带版本标签，避免跨解释器误用。
• 变体：Numba（数值 JIT）、Shed Skin（受限子集 AOT→C++）、
  Cython（混编扩展）、独立可执行文件打包。
• PyPy：运行期类型反馈 + JIT，长循环纯 Python 常更快。
• 一切程序最终都是机器码；差别只在翻译策略（解释 / JIT / AOT）。

【踩坑点】
• 以为 .py 被 CPU 直接执行——总有软件层翻译。
• 把 .pyc 当保密源码分发：易反编译，且绑定解释器版本。
• 混淆「语言」与「CPython 实现」：语法大体统一，
  C扩展与性能模型可能不同。
• 只记「PyPy 更快」：启动时间、兼容性、部分 C 扩展支持不一定更好。

【对你的帮助】
理解运行与性能、.pyc、面试常考点。

【建议掌握程度】
掌握约 90%：五条执行链术语与 CPython 地位。

【章节测验 · 中英对照】

── 第 1 题 ──
Q1 [EN] What is the Python interpreter?
Q1 [中文] 什么是 Python 解释器？
A1 [EN] The Python interpreter is a program that runs the Python programs you
    write. It essentially intermediates between your Python instructions
    and those available in a CPU’s machine code.
A1 [中文] Python 解释器是一个程序，用来运行你编写的 Python 程序。
    它在你的Python指令与 CPU 机器码之间起中介作用。

── 第 2 题 ──
Q2 [EN] What is source code?
Q2 [中文] 什么是源代码？
A2 [EN] Source code is the statements you write for your program. It consists
    of text in text files whose names normally end with a.py extension.
A2 [中文] 源代码是你为程序编写的语句，通常是扩展名为 .py 的文本文件。

── 第 3 题 ──
Q3 [EN] What is bytecode?
Q3 [中文] 什么是字节码？
A3 [EN] Bytecode is the lower-level form of your program after Python compiles
    it. Python automatically stores bytecode in files with a.pyc extension
    when possible, and automatically re-creates it when needed.
A3 [中文] 字节码是 Python 编译后的较低级形式。可能时会自动存为 .pyc，
    并在需要时自动重建。

── 第 4 题 ──
Q4 [EN] What is the PVM?
Q4 [中文] 什么是 PVM？
A4 [EN] The PVM is the Python Virtual Machine—the runtime engine of Python
    that interprets your compiled bytecode.
A4 [中文] PVM 即 Python 虚拟机，是解释已编译字节码的运行时引擎。

── 第 5 题 ──
Q5 [EN] What is machine code?
Q5 [中文] 什么是机器码？
A5 [EN] Machine code is the low-level instructions of the underlying CPU on a
    computing device like a PC or phone. Because this is what every
    program ultimately runs, Python code must be translated to this by a
    software layer like the PVM interpreter, or JIT or AOT compilers.
A5 [中文] 机器码是底层 CPU 的指令。一切程序最终都要落到机器码；
    Python需通过PVM解释，或 JIT/AOT 等再翻译到机器码。

── 第 6 题 ──
Q6 [EN] Name two or more variations on Python’s standard execution model.
Q6 [中文] 举出两种以上对标准执行模型的变体。
A6 [EN] Numba, Shed Skin, and standalone executables are all variations on the
    execution model. In addition, the alternative implementations of
    Python named in the next two answers modify the model in some fashion
    as well—by replacing bytecode and VMs, or by adding JIT and AOT
    compilers.
A6 [中文] 对标准执行模型的变体包括 Numba、Shed Skin、独立可执行文件等；
    另外PyPy/Jython 等替代实现也会通过换字节码/VM 或加 JIT/AOT来修改模型。

── 第 7 题 ──
Q7 [EN] How are CPython, Jython, and IronPython different?
Q7 [中文] CPython、Jython、IronPython 有何不同？
A7 [EN] CPython is the standard and reference implementation of the language.
    Jython and IronPython process Python programs for use in Java and.NET
    environments, respectively; they are alternative compilers for Python.
A7 [中文] CPython 是语言的标准与参考实现。Jython、IronPython 分别把 Python面向Ja
    va 与 . NET 环境处理，属于替代编译/实现路线。

── 第 8 题 ──
Q8 [EN] What are PyPy, Shed Skin, and Cython?
Q8 [中文] PyPy、Shed Skin、Cython 是什么？
A8 [EN] PyPy and Shed Skin are reimplementations of Python targeted at speed.
    PyPy speeds normal Python programs by using runtime type information
    and a JIT compiler to replace some Python bytecode with machine code
    as the program runs. Shed Skin speeds programs with an AOT compiler
    that translates a restricted subset of Python to C++, from which it
    can be fully compiled to machine code to be run as a program or used
    in others. Cython is a Python/C combination that can be compiled into
    machine-code extensions accessible to CPython code.
A8 [中文] PyPy 用运行期类型信息与 JIT，在运行中把部分字节码换成机器码以加速。
    Shed Skin 用 AOT 把受限 Python 子集译为 C++ 再编译。
    Cython是Python/C组合，可编译为 CPython 可调用的机器码扩展。

第 3 章  How You Run Programs
     你如何运行程序
归属：Part I  入门 Getting Started
级别：必读·基础    优先级：高
========================================================================

【我的理解与总结】（加深）
把程序跑起来：REPL、系统命令行、IDLE/IDE、import/reload、exec 等。
模块即命名空间；顶层名字在导入后成为属性。分清系统提示符与 >>>是入门关键。

【扩展理解】
• 开发优先命令行或 IDE；双击图标适合最终用户，不适合看报错。
• import 默认每进程一次；改源码想不重启进程则需 reload，
  或直接重新跑脚本。
• 现代常见：python -m、venv、IDE 调试；reload 更多用于 REPL 探索。
• 脚本入口惯例：if __name__ == '__main__':（后章强化）。
• 运行方式还可：exec、os 系统调用、嵌入式宿主、
  WebAssembly（如Pyodide）等。

【踩坑点】
• 在 >>> 敲系统命令、在 shell 敲未启动解释器的 Python 语句——
  提示符混淆。
• Windows 双击 .py 窗口闪退，看不到 print/traceback。
• from M import x 后再 reload(M)：本地 x 仍可能指向旧对象。
• 模块与标准库同名（如 random.py）导致 import 到自己，错误诡异。
• 依赖图标点击开发：错误窗口一闪而过，浪费大量时间。

【对你的帮助】
真正会“跑起来”，区分 $ 与 >>>。

【建议掌握程度】
掌握约 95%：独立运行脚本；理解 import 一次。

【章节测验 · 中英对照】

── 第 1 题 ──
Q1 [EN] How can you start a Python interactive interpreter session (REPL)?
Q1 [中文] 如何启动交互式解释器（REPL）？
A1 [EN] A Python interactive session can be started by typing a Python command
    line in your system’s console window. Type py on Windows and python3
    everywhere else and type it into a Command Prompt or PowerShell window
    on Windows, Terminal on macOS and Linux, and the Termux app on
    Android. Another alternative is to launch IDLE, as its main Shell
    window is an interactive session. Other IDEs, smartphone apps, and
    browser-based systems may offer REPLs in more unique ways.
A1 [中文] 在系统控制台输入 py（Windows）或 python3（其它平台）启动交互会话；
    也可用 IDLE 的 Shell。其它 IDE、手机应用、浏览器环境也可能提供 REPL。

── 第 2 题 ──
Q2 [EN] Where do you type a system command line to launch a script file?
Q2 [中文] 在哪里输入系统命令行启动脚本？
A2 [EN] You type system command lines in the same interface used to launch an
    interactive session by command line. This is whatever your platform
    provides as a system console: again, Command Prompt or PowerShell on
    Windows, Terminal on macOS and Linux, Termux on Android, or other. You
    type this at the system’s prompt shown as $ in this book, not at the
    Python interactive interpreter’s >>> prompt used to enter Python
    code—be careful not to confuse these prompts, because Python and the
    system shell are different systems.
A2 [中文] 在系统控制台（Windows 的 cmd/PowerShell、macOS/Linux 的 Terminal 等）
    输入系统命令行。那是系统提示符（书中常写作 $），不要与
    Python的>>>混淆。

── 第 3 题 ──
Q3 [EN] Name four or more ways to run the code saved in a script file.
Q3 [中文] 举出四种以上运行脚本的方式。
A3 [EN] Code in a script (really, module) file can be run with system command
    lines, file icon clicks, imports and reloads, the exec built-in
    function, os module tools, and IDE GUI devices such as IDLE’s Run →
    Run Module menu option. Some platforms support more specialized
    launching techniques, like drag and drop on macOS, app UIs on
    smartphones, and web notebooks. In addition, some text editors have
    unique ways to run Python code, some Python programs are provided and
    run as standalone executables, and some systems use Python code in
    embedded mode, where it is run by an enclosing program written in
    another language. Though in its early days, code may also be run in
    web browsers with a Python port to WebAssembly like Pyodide.
A3 [中文] 运行脚本的方式包括：系统命令行、点击图标、import/reload、内置 exec、
    os相关工具、IDLE 的 Run→Run Module 等；还有拖放、手机应用、Notebook、
    编辑器集成、独立可执行文件、嵌入式宿主、WebAssembly（如 Pyodide）等。

── 第 4 题 ──
Q4 [EN] What pitfall is related to clicking file icons on Windows and Linux?
Q4 [中文] 点击文件图标有何陷阱？
A4 [EN] Scripts that print and then exit cause the output file to disappear
    immediately, before you can view the output. input() can pause before
    exit so the output window stays open, but error messages generated by
    your script also appear in an output window that closes before you can
    examine its contents—and before an input() pause is reached. Hence,
    system command lines and IDEs such as IDLE are better for most
    development.
A4 [中文] 点击图标时，打印后立刻退出的脚本窗口可能一闪而过，来不及看输出；
    错误信息窗口也可能在 input() 暂停前就关掉。
    因此开发更宜用命令行或IDLE等 IDE。

── 第 5 题 ──
Q5 [EN] Why might you need to reload a module?
Q5 [中文] 为何可能需要 reload？
A5 [EN] Python imports (i.e., loads) a module only once per process, by
    default, so if you’ve changed its source code and want to run the new
    version without stopping and restarting Python, you’ll have to reload
    it. You must import a module at least once before you can reload it.
    Running files of code from a system shell command line, via an icon
    click, or in an IDE such as IDLE generally makes this a nonissue, as
    those launch schemes usually run the current version of the source
    code file each time. An exec / open pair can avoid reloads too.
A5 [中文] 默认每个进程对同一模块只 import 一次。若改了源码又不想重启 Python，
    就需要 reload。必须先成功 import 过才能 reload。
    从命令行/图标/IDLE直接跑文件通常每次都是最新源码，不太需要 reload；
    exec+open 也可绕过。

── 第 6 题 ──
Q6 [EN] How do you run a script from within the IDLE GUI?
Q6 [中文] 如何在 IDLE 中运行脚本？
A6 [EN] Within the text edit window of the file you wish to run, select the
    window’s Run → Run Module menu option. This runs the window’s source
    code as a top-level script file in IDLE and displays its output back
    in the interactive Python “Shell” window.
A6 [中文] 在要运行的文件编辑窗口选择 Run → Run Module，代码会作为顶层脚本运行，
    输出出现在 Shell 窗口。

── 第 7 题 ──
Q7 [EN] How are modules, attributes, and namespaces related?
Q7 [中文] 模块、属性、命名空间关系？
A7 [EN] Each module file is automatically a namespace—that is, a package of
    variables reflecting the assignments made at the top level of the
    file. Each of the module’s variables becomes an attribute of the
    module when it’s imported and are accessed by “.” qualification or
    from name copies. Namespaces help avoid name collisions in Python
    programs: because each module file is a self-contained namespace,
    files must explicitly import other files in order to use their names.
A7 [中文] 每个模块文件自动是一个命名空间：顶层赋值的变量在导入后成为模块属性，
    用模块名.属性 访问。命名空间有助于避免重名冲突——要用其它文件的名字，
    必须显式导入。

第 4 章  Introducing Python Object Types
     Python 对象类型入门
归属：Part II 类型与运算 Types and Operations
级别：必读·核心    优先级：极高
========================================================================

【我的理解与总结】（加深）
核心类型导航图：数字、字符串、列表、字典、元组、文件、集合，以及布尔、
    None、类型本身。
四个关键词贯穿全书：不可变、序列、映射、多态。后面各章都是在展开这张地图。

【扩展理解】
• 不可变：数字 / str / tuple / frozenset；可变：list / dict / set
  /bytearray。
• 序列：有位置次序，支持索引、切片、拼接；映射：
  键→值（核心类型中主要是 dict）。
• 可迭代 ⊃ 序列：生成器、文件、range、dict（默认迭代键）等也是可迭代。
• 多态：同一操作（如 +）含义取决于对象——不绑死类型才能写出通用代码。
• 类型提示是给人和工具看的，CPython 运行时默认不强制检查。
• 「核心」= 语言内置、常有字面量；文件虽核心但通常用 open() 创建。

【踩坑点】
• tuple 不可变 ≠ 元素不可变：元组里的 list 仍可被改。
• 用 is 比较内容：小整数/短串可能缓存导致「碰巧对」；内容比较用 ==。
• 以为只有 list 能 for：任何可迭代都能。
• 把多态理解成「不用管类型」：仍需约定接口（有哪些操作），
  否则运行期才爆。
• 文件对象忘记关闭（后文 with 解决）。

【对你的帮助】
全书类型体系导航图。

【建议掌握程度】
掌握约 95%：分类类型并解释四个关键词。

【章节测验 · 中英对照】

── 第 1 题 ──
Q1 [EN] Name four of Python’s core object types.
Q1 [中文] 举出四种核心对象类型。
A1 [EN] Numbers, strings, lists, dictionaries, tuples, files, and sets are
    generally considered to be the core object types. Booleans, None, and
    types themselves are classified this way as well. Some of these types
    are really categories: there are multiple number types (integer,
    floating point, complex, fraction, and decimal) and multiple string
    types (text strings, byte strings, and mutable byte strings).
A1 [中文] 核心对象类型通常包括：数字、字符串、列表、字典、元组、文件、集合；
    布尔、 None、类型本身也可归入。其中数字与字符串内部还有多种具体类型（
    如 int/flo at/complex、文本/字节串等）。

── 第 2 题 ──
Q2 [EN] Why are they called “core” object types?
Q2 [中文] 为何叫“核心”类型？
A2 [EN] They are known as “core” object types because they are part of the
    Python language itself and are always available. To create other
    objects, you generally must call functions in imported modules. Most
    of the core objects have specific syntax for generating their objects:
    'hack', for example, is an expression that makes a string and
    determines the set of operations that can be applied to it. Because of
    this, core objects are hardwired into Python’s syntax. In contrast,
    you must call the built-in open function to create a file object, even
    though this is usually considered a core object type too.
A2 [中文] 称「核心」是因为它们属于语言本身、始终可用；
    多数还有字面量语法（如'hack' 生成字符串）。
    其它对象往往要调用导入模块中的函数才能创建。文件虽常算核心，
    但一般通过open 创建。

── 第 3 题 ──
Q3 [EN] What does “immutable” mean, and which three of Python’s object types
    are considered immutable?
Q3 [中文] “不可变”含义？哪三种不可变？
A3 [EN] An “immutable” object is an object that cannot be changed after it is
    created. Numbers, strings, and tuples in Python fall into this
    category. While you cannot change an immutable object in place, you
    can always make a new one by running an expression. bytearrays offer
    mutability for strings, but they only apply directly to text if it’s a
    simple 8-bit kind (e.g., ASCII).
A3 [中文] 不可变指创建后不能原地修改。数字、字符串、元组属于此类。不能原地改，
    但可用表达式生成新对象。bytearray 提供可变字节，
    对简单8位文本才较直接。

── 第 4 题 ──
Q4 [EN] What does “sequence” mean, which objects fall into this category, and
    how is “iterable” related?
Q4 [中文] “序列”含义？与可迭代关系？
A4 [EN] A “sequence” is a positionally ordered collection of objects. Strings,
    lists, and tuples are all sequences in Python. They share common
    sequence operations, such as indexing, concatenation, and slicing, but
    also have type-specific method calls. The related term “iterable”
    means either a physical sequence, or a virtual one that produces its
    items on request. Sequences are iterable, but so are generators,
    files, results of functions like range, and the dictionary object
    (which produces its keys when iterated, just like its keys method).
A4 [中文] 序列是按位置排列的集合：字符串、列表、元组都是，
    并共享索引/拼接/切片等运算，也有各自方法。「可迭代」
    指能产生元素的对象：序列是可迭代，生成器、文件、range、字典（迭代键）
    等也是。

── 第 5 题 ──
Q5 [EN] What does “mapping” mean, and which core object type is a mapping?
Q5 [中文] “映射”含义？哪个是映射？
A5 [EN] The term “mapping” denotes an object that maps keys to associated
    values. Python’s dictionary is the only mapping among its core object
    types. Mappings retain insertion order (as of Python 3.7), and support
    access to data stored by key, plus type-specific method calls that
    enable key tests, iteration, and more.
A5 [中文] 映射把键关联到值。核心类型中字典是映射。自 3.7 起字典保留插入顺序，
    支持按键访问及一批字典方法。

── 第 6 题 ──
Q6 [EN] What is “polymorphism,” and why should you care?
Q6 [中文] 什么是多态？为何重要？
A6 [EN] “Polymorphism” means that the meaning of an operation (like a +)
    depends on the objects being operated on. This turns out to be a key
    idea (and perhaps the largest) behind using Python well—not
    constraining code to specific types makes that code automatically
    applicable to many types. This becomes more obvious when coding
    functions and classes in Python. While Python today has type hinting,
    it’s not used by Python itself and is meant only for documentation and
    tools.
A6 [中文] 多态指运算含义取决于参与运算的对象（如 +）。不把代码绑死在单一类型上，
    才能自动适用于多种类型——这是用好 Python 的关键思想。类型提示存在，
    但运行时默认不强制，主要用于文档与工具。

【我的理解与总结】（加深）
数字类型：运算符优先级、混合类型提升、开方/平方、截断与四舍五入、
    进制显示与解析。
目标：写对表达式，处理显示进制与基础精度问题。

【扩展理解】
• 无括号时乘法高于加法；** 右结合；拿不准就加括号。
• 混合运算向更「宽」类型提升：int+float→float。
• / 真除法总得到 float；// 地板除；% 余数；divmod 同时取商余。

• 用 eval 把用户输入当进制字符串解析：有安全风险，用 int(s, base)。
• 混淆 trunc 与 floor：负数时结果不同。

第 6 章  The Dynamic Typing Interlude
     动态类型插曲
归属：Part II 类型与运算 Types and Operations
级别：必读·核心    优先级：极高
========================================================================

【我的理解与总结】（加深）
动态类型核心心智模型：变量是「名字」，对象在堆上；
    赋值是「让名字指向对象」，不是往盒子里改值。
多个名字可共享同一对象；对可变对象原地修改，所有引用都看得见。
    这是全书最重要的一章。

【扩展理解】
• 画图：名字 → 箭头 → 对象；== 比相等，is 比是否同一对象。
• 不可变「修改」只能产生新对象再绑定；可变可原地改。
• 浅拷贝：L[:] / list(L) / copy.copy；深拷贝：copy.
  deepcopy（嵌套全复制）。
• 共享引用场景：多目标赋值 A=B=[]、函数传参、类属性、默认参数。
• 小 int、部分短 str 可能被缓存，is 比较会制造假安全感。
• 后面 ch11/18/类属性的坑，全部是本章的推论。

【踩坑点】
• A=B=[] 后 A.append 影响 B——同一列表。
• 以为 L[:] 是深拷贝：内层可变对象仍共享。
• 函数默认参数 def f(a=[])：默认对象只建一次，跨调用残留（经典坑）。
• 用 is 比字符串/数字内容（None/True/False 单例除外）。
• 改参数里的列表却疑惑「为什么外面变了」——本来就是同一对象。

【对你的帮助】
Python 最重要心智模型，后面参数/默认值全靠它。

【建议掌握程度】
掌握约 100%：能画引用图判断是否互相影响。

【章节测验 · 中英对照】

── 第 1 题 ──
Q1 [EN] Consider the following three statements. Do they change the value
    printed for A ? A = 'code' B = A B = 'Python'
Q1 [中文] A='code'; B=A; B='Python' 会改变 A 吗？
A1 [EN] No: A still prints as 'code'. When B is assigned to the string
    'Python', all that happens is that the variable B is reset to point to
    the new string object. A and B initially share (i.e., reference/point
    to) the same single string object 'code', but two names are never
    linked together in Python. Thus, setting B to a different object has
    no effect on A. The same would be true if the last statement here were
    B = B + 'coding', by the way—the concatenation would make a new object
    for its result, which would then be assigned to B only. We can never
    overwrite a string (or number, or tuple) in place, because strings are
    immutable.
A1 [中文] 不会改变 A。A 仍为 'code'。B=A 只是让 B 与 A 曾指向同一字符串；
    随后B='Python' 只是让 B 改指向新对象。名字之间不会互相绑定。
    字符串不可变，也无法原地改写。

── 第 2 题 ──
Q2 [EN] Consider these three statements. Do they change the printed value of A
    ? A = ['code'] B = A B[0] = 'Python'
Q2 [中文] A=['code']; B=A; B[0]='Python' 会改变 A 吗？
A2 [EN] Yes: A now prints as ['Python']. Technically, we haven’t really
    changed either A or B; instead, we’ve changed part of the object they
    both reference (point to) by overwriting that object in place through
    the variable B. Because A references the same object as B, the update
    is reflected in A, too.
A2 [中文] 会改变 A。A 与 B 共享同一列表对象；通过 B[0]=... 原地改的是那个列表，
    故 A 也显示 ['Python']。

── 第 3 题 ──
Q3 [EN] How about these—is A changed now? A = ['code'] B = A[:] B[0] =
    'Python'
Q3 [中文] A=['code']; B=A[:]; B[0]='Python' 会改变 A 吗？
A3 [EN] No: A still prints as ['code']. The in-place assignment through B has
    no effect this time because the slice expression made a copy of the
    list object before it was assigned to B. After the second assignment
    statement, there are two different list objects that have the same
    value— in Python, we say they are ==, but not is. The third statement
    changes the value of the list object pointed to by B, but not that
    pointed to by A.
A3 [中文] 不会改变 A。B=A[:] 做了浅拷贝，得到值相等但不是同一对象的新列表（==但
    不是 is）。之后改 B 不影响 A。

第 7 章  String Fundamentals
     字符串基础
归属：Part II 类型与运算 Types and Operations
级别：必读·核心    优先级：极高

【我的理解与总结】（加深）
字符串不可变；方法通常类型专用，表达式与内置函数更通用；三种格式化；
    转义影响「真实长度」。
文本处理与 f-string 是日常刚需。

【扩展理解】
• 「改字符串」= 拼接/切片/replace/格式化 得到新串，再赋回原名。
• find 只用于 str；序列通用操作用 in、切片、len。
• ord/chr：字符与 Unicode 码点互转（不限于 ASCII 0–127）。
• 格式化：% 表达式、str.format、f-string（现代首选，可内嵌表达式）。
• 转义 \n、\xhh、\ooo、\u、\U；r'...' 原始字符串利于正则。
• 循环拼超大串用 join 或列表收集，避免反复分配。

【踩坑点】
• s[0]='x' → TypeError（不可变）。
• 转义串长度直觉错误：r 与普通串、\000 等导致 len 不是「看见的字母数」。
• 八进制转义后紧跟数字可能被吞进转义，写法要清晰。
• str 与 bytes 混用（Py3 严格分离，见 ch37）。
• 格式化混用过多种风格导致团队不一致。

── 第 1 题 ──
Q1 [EN] Can the string find method be used to search a list?
Q1 [中文] 字符串 find 能搜列表吗？
A1 [EN] No, because methods are always type specific; that is, they only work
    on a single object type. Expressions like X + Y and built-in functions

    In this case, for instance, the in membership expression has a similar

    still more type specific than other operation sets.
A1 [中文] 不能。方法是类型专用的。表达式（如 in）与不少内置函数更通用：
    in既可查字符串也可查列表。

Q2 [中文] 字符串切片能用于列表吗？
A2 [EN] Yes. Unlike methods, expressions are generic and apply to many types.
    In this case, the slice expression is really a sequence operation—it

A2 [中文] 能。切片是序列运算，适用于 str/list/tuple 等；切列表得到的是新列表。

A3 [中文] ord(单字符) → 码点整数；chr(整数) → 字符。在 Unicode 模型下这是码点，

Q4 [中文] 如何“修改”字符串？

A4 [中文] 字符串不可变，不能原地改。可通过拼接、切片、replace、

Q5 [中文] S='c, od, e' 如何取中间两字符？

Q6 [EN] How many characters are there in the string "a\nb\x1f\000d" ?
Q6 [中文] "a\nb\x1f\000d" 有多少字符？
A6 [EN] Six. The string "a\nb\x1f\000d" contains the characters a, newline

── 第 7 题 ──
Q7 [EN] Write an expression, method call, and f-string to format 'Python' and
    3.12 at a string’s beginning and end.
Q7 [中文] 用三种方式格式化 'Python' 与 3.12。
A7 [EN] There’s no right answer for what goes in the middle of the result
    string, but as examples: '%s is %s' % ('Python', 3.12) works for the
    expression, and '{} is {}'.format('Python', 3.12) suffices for the
    method call. There’s almost no reason to use an f-string if all parts
    are known and formatted per defaults (f'{'Python'} is {3.12}' seems
    silly), but f-strings are more useful if values are first assigned to
    variables: x='Python'; y=3.12; f'{x} is {y}' or similar garners full
    points.

【我的理解与总结】（加深）
list：有序可变序列；dict：键值映射（3.7+ 保留插入顺序）。

【扩展理解】
• 建列表：[0]*5、字面量、循环 append、列表推导。

Q1 [EN] How might you code a multiple-choice branch in Python?

A1 [EN] An if statement with multiple elif clauses is often the most

Q2 [EN] How can you code an if / else statement as an expression in Python?
Q2 [中文] 如何把 if/else 写成表达式？
A2 [EN] The expression form Y if X else Z returns Y if X is true, or Z

    if statement, and has the potential to produce code that’s hard to

A2 [中文] 三元表达式：Y if X else Z，X 真取 Y 否则 Z。也可用较晦涩的and/or组合，

Q3 [中文] 如何让单语句跨多行？
A3 [EN] Wrap up the statement in an open syntactic pair ((), [], or {}), and
    it can span as many lines as you like; the statement ends when Python

A3 [中文] 用未闭合的 ()[]{} 包裹即可跨多行；也可用反斜杠，但社区普遍不推荐。

A4 [EN] This is partly a review from Chapter 9, but is reinforced in the

A4 [中文] True/False 是布尔真假值，行为上类似整数 1 与 0，

第 13 章  while and for Loops
     while 与 for 循环
归属：Part III 语句与语法 Statements and Syntax
级别：必读·核心    优先级：极高
========================================================================

【我的理解与总结】（加深）
while：通用条件循环；for：自动遍历可迭代。
break 离开、continue 下一轮、else 在「未被 break 正常结束」时执行；
    range 做计数。

【扩展理解】
• 尽量 for x in 可迭代，少手动索引；需要索引用 enumerate。
• for-else 适合「搜索失败」分支，是 Python 特色。
• range 惰性，可表示次数、步长、按位修改列表时的下标。
• while True + break 是常见「先干再判」模式。
• 改正在遍历的序列要小心：迭代副本或建新列表。

【踩坑点】
• 误解 for-else：以为有 else 就执行——实际是没 break 才执行。
• while 忘记更新条件 → 死循环。
• 习惯性 for i in range(len(L))：许多情况直接 for x in L 更好。
• for 里 remove 当前元素会跳过下一个；可倒序删或过滤。
• 在循环里修改了被迭代的 dict/list 导致漏项或异常。

【对你的帮助】
循环是算法基础。

【建议掌握程度】
掌握约 95%。

── 第 1 题 ──
Q1 [EN] What are the main functional differences between while and for loops?
Q1 [中文] while 与 for 主要功能差别？
A1 [EN] The while loop is a general looping statement, but the for is designed
    to automatically iterate across items in a sequence or other iterable.
    Although the while can imitate the for with counter loops, it takes
    more code and might run slower.
A1 [中文] while 是通用条件循环；for 专为遍历序列或其它可迭代对象。while可模仿for
    的计数遍历，但更冗长，也可能更慢。

── 第 2 题 ──
Q2 [EN] What’s the difference between break and continue ?
Q2 [中文] break 与 continue 差别？
A2 [EN] The break statement exits a loop immediately (control flow winds up
    below the entire while or for loop statement), and continue jumps back
    to the top of the loop (control flow winds up positioned just before
    the test in while or the next item fetch in for).
A2 [中文] break 立即离开整个循环；continue 结束本轮，
    回到循环顶部进入下一轮（while 再测条件，for 取下一元素）。

── 第 3 题 ──
Q3 [EN] When is a loop’s else clause executed?
Q3 [中文] 循环 else 何时执行？
A3 [EN] The else clause in a while or for loop will be run once as the loop is
    exiting, if and only if the loop exits normally (i.e., by a false test
    in while or an empty object in for), without running into a break
    statement. A break exits the loop immediately, skipping the else part
    on the way out (if there is one).
A3 [中文] 仅当循环「正常结束」（while 条件变假，或 for 耗尽）且没有 break 时，
    else 子句会执行。break 离开会跳过 else。

── 第 4 题 ──
Q4 [EN] How can you code a counter-based loop in Python?
Q4 [中文] 如何写基于计数器的循环？
A4 [EN] Counter loops can be coded with a while statement that keeps track of
    the index manually, or with a for loop that uses the range built-in
    function to generate successive integer offsets. Neither is the
    preferred way to code in Python, if you need to simply step across all
    the items in a sequence. Instead, use a simple for loop without range
    or counters, whenever possible; it will be easier to code and usually
    quicker to run.
A4 [中文] 可用 while 手动维护索引，或 for i in range(N)。若只是遍历序列元素，
    优先直接 for x in seq，通常更短更快。

── 第 5 题 ──
Q5 [EN] What can a range be used for in a for loop?
Q5 [中文] for 中 range 能做什么？
A5 [EN] The range built-in can be used in a for loop to implement a fixed
    number of repetitions, to scan by offsets instead of items at offsets,
    to skip successive items as you go, and to change a list while
    stepping across it. None of these roles requires range, and most have
    alternatives —scanning actual items, three-limit slices, and list
    comprehensions are often better solutions today (despite the natural
    inclinations of ex–C programmers to want to count things!).
A5 [中文] range 可用于固定次数重复、按偏移扫描、跳步、边遍历边改列表等。
    但许多场景有更好替代：直接遍历元素、切片、推导式等。

第 14 章  Iterations and Comprehensions
     迭代与推导式
归属：Part III 语句与语法 Statements and Syntax
级别：必读·核心    优先级：高
========================================================================

【我的理解与总结】（加深）
迭代协议：可迭代对象 → __iter__ 得迭代器 → 反复 __next__ → StopIteration。
列表推导是「遍历 + 变换/过滤 + 收集」的浓缩；文件最佳逐行方式是forline
    in f。

【扩展理解】
• 手动：it=iter(obj); next(it)。
• 工具家族：for、推导、map/filter、zip、enumerate、sorted、sum、
  any/all、in、join、序列赋值等。
• 列表推导急切物化；生成器/文件惰性，省内存。
• 迭代器通常一次性；range 可反复迭代，生成器耗尽即空。
• 大文件避免 readlines() 一次读入。

【踩坑点】
• 同一生成器/文件 for 两次：第二次没有数据。
• 把 Py3 的 map/zip 当 list：它们是惰性的，需要 list(...) 才物化。
• 推导里堆副作用：难读难调，该用显式 for。
• 迭代中改容器结构。
• 误以为所有可迭代都能 len/下标——迭代器不行。

【对你的帮助】
为生成器与大数据处理打底。

【建议掌握程度】
掌握约 90%。

【章节测验 · 中英对照】

── 第 1 题 ──
Q1 [EN] How are for loops and iterable objects related?
Q1 [中文] for 与可迭代对象关系？
A1 [EN] The for loop normally uses the iteration protocol to step through
    items in the iterable object across which it is iterating. It first
    fetches an iterator from the iterable by calling the iterable’s
    __iter__, and then calls this iterator object’s __next__ method on
    each iteration to advance and catches its StopIteration exception to
    determine when to stop looping. Any object that supports this model
    works in a for loop and in all other iteration tools. The protocol’s
    methods can also be run manually with built-ins iter and next. For
    some objects that are their own iterator, the initial iter call is
    extraneous but harmless.
A1 [中文] for 通过迭代协议工作：先 __iter__ 取迭代器，再反复 __next__ 取元素，
    遇StopIteration 结束。支持该协议的对象都能用于 for 及其它迭代工具；
    也可用 iter/next 手动驱动。

── 第 2 题 ──
Q2 [EN] How are for loops and list comprehensions related?
Q2 [中文] for 与列表推导关系？
A2 [EN] Both are iteration tools. List comprehensions are a concise and often
    efficient way to perform a common for loop task: collecting the
    results of applying an expression to all items in an iterable object.
    It’s always possible to translate a list comprehension to a for loop,
    and part of the list comprehension expression looks like the header of
    a for loop syntactically. The for loop, however, can be used in
    additional looping roles that comprehensions do not address.
A2 [中文] 二者都是迭代工具。列表推导用更简洁的方式完成「对可迭代中每项应用表达式
    并收集结果」；常可改写为 for+append。 for还能做推导覆盖不了的更多循环
    任务。

── 第 3 题 ──
Q3 [EN] Name four iteration tools in the Python language.
Q3 [中文] 举出四种迭代工具。
A3 [EN] Iteration tools in Python include the for loop; list comprehensions;
    the map built-in function; the in membership test expression; and the
    built- in functions sorted, sum, any, and all. This category also
    includes the list and tuple built-ins, string join methods, and
    sequence assignments (starred or not), all of which use the iteration
    protocol (see answer #1) to step across iterable objects one item at a
    time.
A3 [中文] 例如：for、列表推导、map、成员 in、sorted/sum/any/all，
    以及list/tuple、 join、序列解包等——它们都使用迭代协议。

── 第 4 题 ──
Q4 [EN] What is the best way to read line by line from a text file today?
Q4 [中文] 今天逐行读文本文件的最佳方式？
A4 [EN] The “best” way to read lines from a text file today is to not read it
    explicitly at all: instead, open the file within an iteration tool
    such as a for loop or list comprehension, and let the iteration tool
    automatically scan one line at a time by running the file’s next
    handler method on each iteration. This approach is generally best in
    terms of coding simplicity, memory space, and possibly execution speed
    requirements.
A4 [中文] 今天最佳做法往往是：不要一次性显式全读；用 for line in open(...)
    或with打开后迭代，让迭代工具每次取一行。通常更简单、更省内存，
    也可能更快。

第 16 章  Function Basics
     函数基础
归属：Part IV 函数与生成器 Functions and Generators
级别：必读·核心    优先级：极高

【我的理解与总结】（加深）
函数是消除重复、复用与分治的基本单元。
def 被执行时才创建函数对象；调用时才跑函数体；无 return 则返回 None。
避免无谓类型检查，以保留多态与复用。

【扩展理解】
• def 是语句，可出现在模块导入、交互、甚至其它语句块中。
• 返回多个值实质是返回元组。
• 接口思维：关心对象「能做什么」，不关心「叫什么类型」。
• 类型注解可选；要运行时强制需额外库或检查器。
• 函数也可作一等对象：传参、返回、放容器。

【踩坑点】
• 以为 def 时就执行体——只有调用才执行。
• 漏 return：得到 None 再取属性 → AttributeError，报错点远离真相。
• 到处 isinstance 检查：毁掉鸭子类型，函数变脆。
• 可变默认参数（ch18 详述）。
• 函数既改全局又改参数又返回：副作用失控。

【对你的帮助】
代码复用分水岭。

【建议掌握程度】
掌握约 95%。

【章节测验 · 中英对照】

── 第 1 题 ──
Q1 [EN] What is the point of coding functions?
Q1 [中文] 写函数的意义？
A1 [EN] Functions are the most basic way of avoiding code redundancy in
    Python—factoring code into functions means that we have only one copy
    of an operation’s code to update in the future. Functions are also the
    basic unit of code reuse in Python—wrapping code in functions makes it
    a reusable tool, callable in a variety of programs. Finally, functions
    allow us to divide a complex system into manageable parts, each of
    which may be developed individually. Functions are also used for
    object methods, but we’re postponing this role until we study classes.
A1 [中文] 函数避免代码重复（一处修改）、成为复用单元（多处调用），
    并把复杂系统拆成可管理的部分。也用于对象方法（类部分再讲）。

── 第 2 题 ──
Q2 [EN] At what time does Python create a function?
Q2 [中文] Python 何时创建函数？
A2 [EN] A function is created when Python reaches and runs a def statement,
    which creates a function object and assigns it to the function’s name.
    This normally happens when the enclosing module file is imported by
    another module (recall that imports run the code in a file from top to
    bottom, including any def s), but it can also occur when a def is
    typed interactively or nested in other statements, such as if s.
    Functions are also created when a lambda is reached and run, though
    this doesn’t normally happen during an import operation.
A2 [中文] 运行到 def（或 lambda）时创建函数对象并绑定名字。
    通常发生在模块被import 时自上而下执行；也可在交互输入或嵌套语句中发生。

── 第 3 题 ──
Q3 [EN] What does a def function return if it has no return statement in it?
Q3 [中文] 无 return 时函数返回什么？
A3 [EN] A def function returns the None object by default if the control flow
    falls off the end of the function body without running into a return
    statement. Such functions are usually called with expression
    statements, as assigning their None results to variables is generally
    pointless. A return statement with no expression in it also returns
    None. A lambda implicitly returns its expression’s result, so it has
    no default.
A3 [中文] 若控制流走到函数末尾仍无 return，则返回 None。
    无表达式的return也是None。lambda 隐式返回表达式结果，没有这种默认。

── 第 4 题 ──
Q4 [EN] When does the code nested inside the function definition run?
Q4 [中文] 函数定义内部代码何时运行？
A4 [EN] The function body (the code nested inside the function def statement
    or following the colon in lambda) is run when the function is later
    invoked with a call expression. The body runs anew each time the
    function is called.
A4 [中文] 函数体在函数被调用时执行，且每次调用都会重新执行；不是在 def 时执行。

── 第 5 题 ──
Q5 [EN] What’s wrong with checking the types of objects passed into a
    function?
Q5 [中文] 检查传入对象类型有何不好？
A5 [EN] Checking the types of objects passed into a function effectively
    breaks the function’s flexibility, constraining the function to work
    on specific types only. Without such checks, the function would likely
    be able to process an entire array of object types—any objects that
    support the interface expected by the function will work. (The term
    interface means the set of methods and expression operators the
    function’s code runs.) 1 This code will always work if we intersect
    files’ contents obtained with file.readlines(). It may not work to
    intersect lines in open input files directly, though, depending on the
    file object’s implementation of the in operator or general iteration.
    Files must generally be rewound (e.g., with a file.seek(0) or another
    open) after they have been read to end-of-file once, and so are
    single-pass iterators. As you’ll see in Chapter 30 when we study
    operator overloading, objects implement the in operator either by
    providing the specific __contains__ method or by supporting the
    general iteration protocol with the __iter__ or older __getitem__
    methods; classes can code these methods arbitrarily to define what
    iteration means for their data.
A5 [中文] 检查并限制具体类型会破坏灵活性，使函数只能服务少数类型。不做死检查时，
    任何支持所需接口（方法/运算符）的对象都可能工作——这就是多态。
    有特殊需求时再考虑显式检查或类型提示工具。

级别：必读·核心    优先级：极高
========================================================================

【我的理解与总结】（加深）
作用域 LEGB：Local → Enclosing(闭包) → Global(模块) → Builtins。
函数内赋值默认创建局部名；要改外层须 global / nonlocal。
闭包与状态保持是装饰器、回调的基础，必须 100% 会推输出题。

【扩展理解】
• 只引用未赋值：沿 LEGB 查找；有赋值无声明：整函数该名变局部。
• global：改模块全局；nonlocal：改外层函数局部（不能是全局）。
• 跨调用保状态：global、闭包+nonlocal、默认参数、函数属性、类实例、
  可变对象原地改。
• 嵌套函数可读外层局部（闭包），形成 E 层。
• 别覆盖内置名（list、str、id…）。

【踩坑点】
• 先 print(X) 再 X=1 → UnboundLocalError（X 已属局部但尚未绑定）。
• 嵌套函数内赋值以为改外层：无 nonlocal 只是内层新局部。
• 循环变量晚绑定：for 里造 lambda 全变成最终值——用默认参数绑当前值。
• global 滥用导致隐式耦合、难测、线程不安全。
• 与「模块级常量」混淆，随意改全局。

【对你的帮助】
作用域是装饰器/闭包前置课。

【建议掌握程度】
掌握约 95%–100%（追踪输出题必会）。

【我的理解与总结】（加深）
参数传递与匹配：位置、关键字、默认值、*args、**kwargs、调用处解包。
传的是对象引用：不可变对象在函数内重绑不影响调用方；可变对象原地改则影响。
默认可变参数是头号坑，必须会。

【扩展理解】
• 定义大致顺序：普通位置 → 默认 → *args →仅关键字→**kwargs（细节随版本
  演进）。
• 调用：func(1, 2)、func(a=1)、func(*seq)、func(**dict)。
• * 在定义侧收集多余位置成元组；** 收集多余关键字成字典。
• 文档应写清：参数是否会被原地修改。
• 跟踪每题 print 输出是练「匹配规则」的最好办法。

【踩坑点】
• def f(a=[])：默认列表进程内共享，多次调用累积垃圾——
  改用None内部新建。
• 同一参数既位置又关键字传入 → TypeError。
• 可变列表/字典入参被内部改掉，调用方「莫名其妙」变了。
• 仅关键字参数忘记 * 分隔写错签名。
• 把 *args 当 list 去 append 改「调用方」——改的是新元组/结构，别混。

【对你的帮助】
API 与坑（默认可变参数）高发区。

掌握约 100%：每题输出都要能推。

【我的理解与总结】（加深）
函数杂项：lambda、map/filter/reduce、注解、递归、设计准则、结果回传方式。
形成「函数工具箱」与良好风格。

【扩展理解】
• lambda：单表达式匿名函数，适短回调；复杂逻辑用 def。
• map 映射、filter 过滤（惰性）；reduce 在 functools 里做归约；
  常可用推导替代。
• 注解存 __annotations__，运行时不自动强制。
• 递归：基线条件 + 向基线推进；深度有限，深树用显式栈/队列。
• 回传结果：return 优先；约定下改可变参数；少用 global；
  也可抛异常表达失败。
• 设计：单一职责、小而完整、明确输入输出、减少隐藏副作用。

【踩坑点】
• lambda 里写语句块：语法不允许。
• 递归超深度 → RecursionError。
• 把注解当运行时类型校验。
• reduce 可读性差时硬用，团队难维护。
• 通过改全局传递结果：调用关系不透明。

【对你的帮助】
函数工具箱。

── 第 1 题 ──
Q1 [EN] How are lambda expressions and def statements related?
Q1 [中文] lambda 与 def 关系？
A1 [EN] Both lambda and def create function objects to be called later.
    Because lambda is an expression, though, it returns a function object
    instead of assigning it to a name, and it can be used to nest a
    function definition in places where a def will not work syntactically.
    A lambda allows for only a single implicit return value expression,
    though; because it does not support a block of statements, it is not
    ideal for larger functions.
A1 [中文] lambda 与 def 都创建可调用的函数对象。lambda 是表达式，

    不适合大函数。

── 第 2 题 ──
Q2 [EN] What’s the point of using lambda ?
Q2 [中文] 使用 lambda 的意义？
A2 [EN] lambda allows us to “inline” small units of executable code, defer its
    execution, and provide it with state in the form of default arguments
    and enclosing scope variables. Using a lambda is never required; you
    can always code a def instead and reference the function by name.
    lambda comes in handy, though, to embed small pieces of deferred code
    that are unlikely to be used elsewhere in a program. It commonly
    appears in callback-based programs such as GUIs, and has a natural
    affinity with functional tools like map and filter that expect a
    processing function.
A2 [中文] lambda 用于内联小段延后执行的代码，并可借助默认参数与闭包携带状态。
    从不是必须，都可写成 def；常见于 GUI 回调，

── 第 3 题 ──
Q3 [EN] Compare and contrast map, filter, and reduce.
Q3 [中文] 比较 map、filter、reduce。
A3 [EN] These three built-in functions all apply another function to items in

    each item to the function and collects call results, filter collects
    items for which the function returns a true value, and reduce computes
    a single value by applying the function to an accumulator and
    successive items. Unlike the other two, reduce is available in the
    functools module, not the built-in scope (in modern Python history, at
    least).
A3 [中文] 三者都把函数作用在可迭代的元素上：map 收集变换结果，
    filter收集使函数为真的元素，reduce 累积成单值。现代 Python

Q4 [中文] 函数注解是什么？如何用？

A4 [中文] 函数注解是参数与返回值上的可选语法标注，收集在 __annotations__ 里。

Q5 [EN] What are recursive functions, and how are they used?
Q5 [中文] 递归函数是什么？

A5 [中文] 递归函数直接或间接调用自己以重复工作。适任意形状结构遍历，

第 20 章  Comprehensions and Generations
     推导式与生成
归属：Part IV 函数与生成器 Functions and Generators
级别：必读·核心    优先级：极高
========================================================================

【我的理解与总结】（加深）
[] 列表推导：立即建整表；() 生成器表达式：惰性逐个产出。
函数体含 yield → 生成器函数，调用得生成器对象，可暂停/恢复。
map vs 推导；async/await 异步模型初识。

【扩展理解】
• 生成器省内存、一次遍历；list(g) 可物化。
• yield 产出并暂停；next/for 恢复；send 可传入值（进阶）。
• yield from 委托子生成器。
• 推导支持多 for 与 if 过滤；嵌套过深改为普通循环。
• async def 定义协程；await 等待；需事件循环（asyncio）；
  与线程/进程是不同并发模型。
• 生成器函数用 return 会结束并附 StopIteration 值，普通for拿不到该值。

【踩坑点】
• 生成器用两次：第二次为空。
• 大结果用列表推导导致内存爆——该用生成器表达式。
• 未搞懂事件循环就 async：同步阻塞调用卡住整个 loop。
• 用含 yield 的函数却当普通函数要返回值用。
• 生成器与协程概念混淆。

【对你的帮助】
Pythonic 数据处理主力。

【建议掌握程度】
掌握约 95%（async 了解即可）。

【章节测验 · 中英对照】

── 第 1 题 ──
Q1 [EN] What is the difference between enclosing a list comprehension in
    square brackets and parentheses?
Q1 [中文] 列表推导用[]与()的差别？
A1 [EN] List comprehensions in square brackets produce the result list all at
    once in memory. When they are enclosed in parentheses instead, they
    are actually generator expressions—they have the same internal syntax
    and a similar meaning but do not produce the result list all at once.
    Instead, generator expressions return a generator object, which yields
    one item in the result at a time when used in an iteration tool or
    iterated manually with next.
A1 [中文] 方括号列表推导会一次在内存中生成整个结果列表；
    改用圆括号则是生成器表达式：语法相似，但返回生成器，在迭代时逐个产出。

── 第 2 题 ──
Q2 [EN] How are generators and iterators related?
Q2 [中文] 生成器与迭代器关系？
A2 [EN] Generators are iterable objects that support the iteration protocol
    automatically—they have an iterator with a __next__ method (run by
    next) that repeatedly advances to the next item in a series of results
    and raises an exception at the end of the series. In Python, we can
    code generator functions with def and yield, generator expressions
    with parenthesized comprehensions, and generator objects with classes
    that define a special method named __iter__ (discussed later in the
    book).
A2 [中文] 生成器是自动支持迭代协议的可迭代对象：有 __next__，
    可前进并在结束时引发异常。可用 def+yield 写生成器函数，
    用圆括号推导写生成器表达式，或用类定义 __iter__ 等。

── 第 3 题 ──
Q3 [EN] How can you tell if a function is a generator function?
Q3 [中文] 如何判断函数是生成器函数？
A3 [EN] A generator function has a yield statement (with or without its from
    extension) somewhere in its code. Generator functions are otherwise
    identical to normal functions syntactically, but they are compiled
    specially to return an iterable generator object when called. That
    object retains state and code location between values. (This means
    that deleting yield makes a function normal, but code deletions can
    cause all sorts of issues.)
A3 [中文] 若函数体中出现 yield（或 yield from），它就是生成器函数：
    调用时返回生成器对象，而不是一次性跑完并返回普通值。

── 第 4 题 ──
Q4 [EN] What does a yield statement do?
Q4 [中文] yield 做什么？
A4 [EN] When present, this statement makes Python compile the function
    specially as a generator; when called, the function returns a
    generator object that supports the iteration protocol. When the yield
    statement is run, it sends a result back to the caller and suspends
    the function’s state; the function can then be resumed after the last
    yield statement, in response to a next built-in or __next__ method
    call issued by the caller. In more advanced roles, the generator send
    method similarly resumes the generator, but can also pass a value that
    shows up as the yield expression’s value. Generator functions may also
    have a return statement, which terminates the generator (and attaches
    an optional value to the automatic StopIteration exception).
A4 [中文] yield 使函数按生成器编译；执行到 yield 时把值交给调用方并暂停状态，
    下次 next 从暂停处继续。还可用 send 传入值；
    return会结束生成器（可选值附在 StopIteration 上）。

── 第 5 题 ──
Q5 [EN] How are map calls and list comprehensions related? Compare and
    contrast the two.
Q5 [中文] map 与列表推导比较？
A5 [EN] The map call is similar to a list comprehension—both produce a series
    of values, by collecting the results of applying an operation to each
    item in a sequence or other iterable, one item at a time. The primary
    difference is that map applies a function call to each item, and list
    comprehensions apply arbitrary expressions. Because of this, list
    comprehensions are more general; they can apply a function call
    expression like map, but map requires a function to apply other kinds
    of expressions. List comprehensions also support extended
    syntax—nested for loops, and if clauses that subsume the filter
    built-in. map also differs by producing a generator of values; the
    list comprehension materializes the result list in memory all at once,
    and this may matter for large lists.
A5 [中文] map 与列表推导都能对可迭代各项做操作并收集结果。map 主要套函数；
    推导可写任意表达式，还支持多 for 与 if（涵盖 filter）。
    列表推导立即物化；map 在 Py3 惰性。对内置函数，CPython 上map有时更快；
    推导常更清晰灵活。

── 第 6 题 ──
Q6 [EN] What do async def and await mean in a Python script?
Q6 [中文] async def 与 await 含义？
A6 [EN] The async def is used to define an asynchronous function (usually
    called a coroutine), and await waits for another asynchronous object
    to produce its value, possibly yielding control back to an event loop
    to allow other code to run during the wait. async def is required to
    use await, async for, and async with, and both an event loop and
    scheduling calls in module asyncio are generally required to achieve
    concurrency in this model. There’s more to the async story than told
    here; see Python’s manuals for next steps on this topic, as well as
    its multithreading and multiprocessing alternatives in Python’s
    standard library.
A6 [中文] async def 定义异步函数（协程）；await 等待可等待对象完成，
    等待期间可把控制权交回事件循环。使用 async for/with 等也需异步函数。
    通常还要 asyncio 事件循环与调度才能实现并发。另有多线程/多进程等模型。

第 23 章  Module Coding Basics
     模块编码基础
归属：Part V  模块与包 Modules and Packages
级别：必读·核心    优先级：极高
========================================================================

【我的理解与总结】（加深）
任何含 Python 语句的 .py 都是模块，无需特殊声明。
import 引入模块对象；from 再把名字拷到当前作用域；reload强制重新执行源码。
from 有三大隐患：含义模糊、覆盖本地名、与 reload 不同步。

【扩展理解】
• from M import x：x 与 M.x 曾指向同一对象；
  M内再赋值x不会更新你的本地名。
• 同名冲突：用 import M 限定，或 as 别名。
• reload 在 importlib 中；仅适合开发期，生产热更极危险。
• from * 受 _前缀 与 __all__ 约束（见 ch25）。
• 需要模块对象本身、或要 reload 时，优先 import。

【踩坑点】
• from M import * 污染命名空间，静态分析与阅读困难。
• from 之后 reload(M)：本地绑定仍是旧对象。
• 星号导入覆盖已有函数/变量，静默改行为。
• 循环 from 导致部分初始化 AttributeError。
• 在包外当脚本跑时相对 from 失败。

【对你的帮助】
会拆模块写库。

【建议掌握程度】
掌握约 95%。

【章节测验 · 中英对照】

── 第 1 题 ──
Q1 [EN] How do you make a module?
Q1 [中文] 如何制作模块？
A1 [EN] To create a module, you simply write a text file containing Python
    statements; every source code file is automatically a module, and
    there is no syntax for declaring one. Import operations load module
    files into module objects in memory. You can also make a module by
    writing code in an external language like C or Java, but such
    extension modules are beyond the scope of this book (and most of its
    readers).
A1 [中文] 写一个包含 Python 语句的文本文件即可，每个源码文件自动是模块，
    没有特殊「模块声明」语法。import 把它加载为内存中的模块对象。
    也可用C/Java 等写扩展模块，但超出本书范围。

── 第 2 题 ──
Q2 [EN] How is the from statement related to the import statement?
Q2 [中文] from 与 import 关系？
A2 [EN] The from statement imports an entire module, like the import
    statement, but as an extra step, it also copies one or more variables
    from the imported module into the scope where the from appears. This
    enables you to use the imported names directly (name) instead of
    having to go through the module (module.name).
A2 [中文] from 也会导入整个模块，但额外把其中若干名字复制到 from 所在作用域，
    从而可直接用 name 而不必 module.name。对象本身仍是共享的。

── 第 3 题 ──
Q3 [EN] How is the reload function related to imports?
Q3 [中文] reload 与 import 关系？
A3 [EN] By default, a module is imported only once per process. The reload
    function forces a module to be imported again. It is mostly used to
    pick up new versions of a module’s source code during development, and
    in dynamic customization scenarios where users change part of a system
    without restarting it.
A3 [中文] 默认每进程 import 一次。reload 强制再次导入/执行模块源码，
    多用于开发期加载新版本，或运行中动态定制。

── 第 4 题 ──
Q4 [EN] When must you use import instead of from ?
Q4 [中文] 何时必须用 import 而不是 from？
A4 [EN] You must use import instead of from only when you need to access the
    same name in two different modules. To make the two names unique,
    qualify with the names of their enclosing modules obtained with
    import. The as extension can render from usable in this context as
    well, by renaming imports uniquely.
A4 [中文] 当需要区分两个模块中的同名对象时，应用 import 通过模块名限定；
    也可用from ... as 起不同别名。需要模块对象本身或配合reload等场景也更适
    合import。

── 第 5 题 ──
Q5 [EN] Name three potential pitfalls of the from statement.
Q5 [中文] from 的三个潜在陷阱？
A5 [EN] The from statement can obscure the meaning of a variable (which module
    it is defined in), can have problems with the reload call (names may
    reference prior versions of objects), and can corrupt namespaces (it
    might silently overwrite names you are using in your scope). The from
    * form is worse in most regards—it can corrupt namespaces arbitrarily
    and obscure the meaning of variables, so it is probably best used
    sparingly.
A5 [中文] from 的隐患：变量来源变模糊；与 reload 配合时本地名可能仍指旧对象；

【我的理解与总结】（加深）
包：层次化模块目录。常规包可用 __init__.py 声明/初始化；相对导入 from
    .import name。
命名空间包可不靠单一 __init__，内容可跨多目录。

【扩展理解】
• 绝对导入从 sys.path 找；包内相对导入只在包上下文中可靠。
• import as、from 可缩短长路径；__init__ 可再导出公共 API。
• __init__.py 首次导入包时执行，其赋值成包属性。
• 目录结构应反映 API 边界，避免过深过碎。
• 安装后的可编辑包与 src 布局是工程常见实践。

【踩坑点】
• python path/to/mod.py 直接跑包内模块：相对导入炸。
• __init__ 里重逻辑 + 循环依赖，错误极难查。
• 混用相对/绝对风格，团队不统一。
• 以为「没有 __init__ 就一定不是包」——命名空间包规则更细。
• 包名与本地测试脚本目录冲突。

【对你的帮助】
中大型目录结构。

── 第 1 题 ──
Q1 [EN] What is the purpose of an __init__.py file in a module package
    directory?
Q1 [中文] __init__.py 在包目录中的目的？
A1 [EN] The __init__.py file serves to declare and initialize a regular module
    package; Python automatically runs its code the first time you import
    through a directory in a process. Its assigned variables become the
    attributes of the module object created in memory to correspond to
    that directory. It’s optional for package folders but gives a folder
    search precedence over other folders of the same name that don’t have

A1 [中文] __init__.py 用于声明并初始化常规包；进程中首次通过该目录导入时会执行它

Q2 [中文] 如何避免每次写完整包路径？

A3 [中文] 早期常规包目录需要 __init__.py；引入命名空间包后变为在很多情况下可选。

── 第 6 题 ──
Q6 [EN] What is a namespace package?
Q6 [中文] 什么是命名空间包？
A6 [EN] A namespace package is an extension to the import model that
    corresponds to one or more directories that do not have __init__.py
    files. When Python finds these during an import search and does not
    find a simple module or regular package first, it creates a namespace
    package that is the virtual concatenation of all found directories
    having the requested module name. Further nested components are looked
    up in all the namespace package’s directories. The effect is similar
    to a regular package, but content may be split across multiple

【我的理解与总结】（加深）
模块进阶：_ 前缀与 __all__；__name__=='__main__' 双模式；遍历属性；

【扩展理解】
• 单下划线：from * 默认不导出；__all__ 正向列出可导出名。

【我的理解与总结】（加深）
OOP 要点是复用：通过定制已有代码减少冗余，而不是复制粘贴后各改各的。

第 27 章  Class Coding Basics
     类编码基础
归属：Part VI 类与 OOP Classes and OOP
级别：必读·核心    优先级：极高

【我的理解与总结】（加深）
类嵌在模块中，是模块的属性；类与模块都是命名空间，但类支持多实例、
    继承、运算符重载。
类属性在 class 体赋值；实例属性通常 self.x=；重载靠双下划线特殊方法。
读懂 OOP 代码的三块基石：self、继承查找、__init__。

【扩展理解】
• 运算符重载：__add__/__str__/__repr__ 等，
  出现在对应运算时由Python调用。
• 只在对象语义像内置类型、或需要契合某 API 时再重载。
• 最常用 __init__，其次 __repr__/__str__。
• 实例属性建议在 __init__ 集中初始化，避免「有时有有时无」。
• 模块 ≈ 单例文件命名空间；类 ≈ 可复制出很多带状态的对象。

【踩坑点】
• 类属性 list/dict 被所有实例共享，误当每实例一份。
• 方法里 x=1 只是局部变量，不会变成实例属性（要 self.x=1）。
• 过度重载使代码变「魔术」，阅读成本高。
• __init__ 里做太重的 I/O/网络，导致 new 对象极慢、难测。
• 混淆类方法/实例方法/静态方法（见后章）。

A2 [EN] Shelves (really, the pickle module they use) automatically relink an

A2 [中文] shelve/pickle 在加载时会按保存的信息把实例重新接到它的类：

── 第 3 题 ──
Q3 [EN] Why is it so important to move processing into methods, instead of
    hardcoding it outside the class?
Q3 [中文] 为何把处理放进方法而不是类外写死？
A3 [EN] It’s important to move processing into methods so that there is only

    on any instance. This is Python’s notion of encapsulation —wrapping up
    logic behind interfaces, to better support future code maintenance. If

A3 [中文] 把处理放进方法能保证未来只改一处，且任何实例都能用——这就是封装：
    把逻辑藏在接口后，降低演化成本，避免脚本里重复硬编码。

── 第 4 题 ──
Q4 [EN] Why is it better to customize by subclassing rather than copying the

Q4 [中文] 为何用子类定制优于复制修改？
A4 [EN] Customizing with subclasses reduces development effort. In OOP, we

    leverage what we’ve already done. This is much better than either
    starting from scratch each time, or introducing multiple redundant
    copies of code that may all have to be updated in the future.
A4 [中文] 用子类定制能减少工作量：扩展已有工作而非复制或直接改原码，
    避免多份冗余拷贝将来要同步修改。这是 OOP 的大思想之一。

Q5 [中文] 为何回调超类方法跑默认动作优于复制代码？
A5 [EN] Copying and modifying code doubles your potential work effort in the

A5 [中文] 复制超类代码会使未来双倍维护。需要默认行为时，应通过超类名或 super()

── 第 6 题 ──

Q6 [中文] 为何用 __dict__ 等通用工具优于每类手写定制？

    of the primary assets classes bring to the table.
A6 [中文] 通用工具（如基于 __dict__ 的通用 __repr__）

Q7 [中文] 何时选嵌入组合而非继承？
A7 [EN] Inheritance is best at coding extensions based on direct customization

A7 [中文] 继承适合 is-a 的直接定制（如 Manager 特化 Person）；
    组合适合把多个对象聚合成整体并由控制器调度（has-a）。二者常一起用：

【我的理解与总结】（加深）
类细节：抽象超类（定义钩子由子类实现）、类级赋值共享、
    手动串联__init__、增强而非替换方法、类体作用域特殊规则。

【扩展理解】
• 抽象超类/模板方法：框架调用 self.hook()，子类提供 hook。
• 可用 abc. ABC / @abstractmethod 更早发现未实现。
• 子类定义了 __init__ 常需显式 Super.__init__(self,...)
  或super().__init__(...)。

• 抽象方法运行到才失败，缺少 abc 时错误滞后。
• super() 在多继承下的顺序与预期不符（先看 __mro__）。
• 用类属性可变对象当「每实例状态」。

── 第 1 题 ──
Q1 [EN] What is an abstract superclass?
Q1 [中文] 什么是抽象超类？
A1 [EN] An abstract superclass is a class that calls a method, but does not
    inherit or define it—it expects the method to be filled in by a

    手法。

── 第 2 题 ──
Q2 [EN] What happens when a simple assignment statement appears at the top
    level of a class statement?
Q2 [中文] class 顶层简单赋值会发生什么？
A2 [EN] When a simple assignment statement (X = Y) appears at the top level of

A2 [中文] class 顶层的简单赋值 X=Y 会创建类的数据属性 Class. X，

Q3 [EN] Why might a class need to manually call the __init__ method in a

Q3 [中文] 为何类可能需手动调用超类 __init__？
A3 [EN] A class must manually call the __init__ method in a superclass if it

    inheritance tree. Superclass constructors are often called through the

A3 [中文] 若子类自己定义了 __init__ 仍希望超类构造逻辑运行，

Q4 [中文] 如何增强而非完全替换继承方法？
A4 [EN] To augment instead of completely replacing an inherited method,

    of the method manually: Superclass. method (self, …); or do so

    special case of this one.
A4 [中文] 在子类重定义该方法，但在新实现里手动回调超类版本（

── 第 5 题 ──
Q5 [EN] How does a class’s local scope differ from that of a function?
Q5 [中文] 类的局部作用域与函数有何不同？
A5 [EN] A class is a local scope and has access to enclosing local scopes, but

A5 [中文] class 也是局部作用域且能看见外层，但它不会作为「再嵌套代码的enclosing

第 30 章  Operator Overloading
     运算符重载
归属：Part VI 类与 OOP Classes and OOP
级别：必读·进阶    优先级：高
========================================================================

【我的理解与总结】（加深）
运算符重载实践：迭代 __iter__/__getitem__；显示 __str__/__repr__；
    切片走 __getitem__(slice)；原地加 __iadd__。
原则：语义自然才重载，否则用普通方法名。

【扩展理解】
• for 优先找 __iter__ 返回迭代器；没有则退回 __getitem__ 下标 0,1,2...
• __str__ 面向用户（print/str）；__repr__面向调试/交互/无__str__时的回
  退。
• 切片：__getitem__ 收到 slice 对象；赋值还有 __setitem__。
• x+=y 先试 __iadd__，否则可能 __add__ 再重绑。
• 还有 __radd__ 等「右操作」反射方法。
• yield 也可辅助实现迭代器协议。

【踩坑点】
• 只写 __str__：交互回显仍难看，建议同时写好 __repr__。
• __iter__ 返回 self 且状态不可重入：嵌套 for 互相干扰。
• __iadd__ 忘记 return self：x+=y 得到 None。
• 为重载而重载，运算符含义牵强。
• __getitem__ 与 __iter__ 行为不一致，用户困惑。

【对你的帮助】
让对象用起来像内置类型。

【建议掌握程度】
掌握约 85%。

【章节测验 · 中英对照】

── 第 1 题 ──
Q1 [EN] What two operator-overloading methods can you use to support iteration
    in your classes?
Q1 [中文] 支持迭代的两个重载方法？
A1 [EN] Classes can support iteration by defining (or inheriting) __getitem__
    or __iter__. In all iteration tools, Python tries to use __iter__
    first, which returns an object that supports the iteration protocol
    with a __next__ method: if no __iter__ is found by inheritance search,
    Python falls back on the __getitem__ indexing method, which is called
    repeatedly, with successively higher indexes. If used, the yield
    statement can create the __next__ method automatically.
A1 [中文] 可定义 __iter__（优先：返回带 __next__ 的迭代器）或__getitem__（按0,1,
    2... 下标回退）。yield 可自动帮助产生 __next__行为。

── 第 2 题 ──
Q2 [EN] What two operator-overloading methods handle printing, and in what
    contexts?
Q2 [中文] 处理打印的两个方法及场景？
A2 [EN] The __str__ and __repr__ methods implement object print displays. The
    former is called by the print and str built-in functions; the latter
    is called by print and str if there is no __str__, and always by the
    repr built-in, interactive echoes, and nested appearances. That is,
    __repr__ is used everywhere, except by print and str when a __str__ is
    defined. A __str__ is usually used for user-friendly displays;
    __repr__ gives extra details or the object’s as-code form. String
    formatting runs these methods too.
A2 [中文] __str__ 由 print/str 使用（用户友好）；__repr__ 在无 __str__时也可被pr
    int/str 使用，并总被 repr、交互回显、嵌套显示等使用。
    格式化也会触发它们。

── 第 3 题 ──
Q3 [EN] How can you intercept slice operations in a class?
Q3 [中文] 如何拦截切片？
A3 [EN] Slicing is caught by the __getitem__ indexing method: it is called
    with a slices object instead of a simple integer index, and slice
    objects may be passed on or inspected as needed.
A3 [中文] 切片由 __getitem__ 拦截：传入的是 slice 对象而不是普通整数下标；
    可检查或继续传递该 slice。

── 第 4 题 ──
Q4 [EN] How can you catch in-place addition in a class?
Q4 [中文] 如何捕获原地加法？
A4 [EN] In-place addition tries __iadd__ first, and __add__ with an assignment
    second. The same policy holds true for all binary operators. The
    __radd__ method is also available for right-side addition.
A4 [中文] 原地加法先尝试 __iadd__；若无则可能退到 __add__ 再赋值。
    其它原地二元运算类似；还有 __radd__ 处理右操作数情况。

── 第 5 题 ──
Q5 [EN] When should you provide operator overloading?
Q5 [中文] 何时提供运算符重载？
A5 [EN] When a class naturally matches, or needs to emulate, a built-in type’s
    interfaces. For example, collections might imitate sequence or mapping
    interfaces, and callables might be coded for use with an API that
    expects a function. You generally shouldn’t implement expression
    operators if they don’t naturally map to your objects naturally and
    logically, though—use normally named methods instead.
A5 [中文] 当类自然匹配或需要模拟内置类型接口时（如序列、映射、可调用）。
    若运算符并不自然对应对象语义，就用普通方法名，不要为重载而重载。

【扩展理解】

    in a higher common superclass in multiple-inheritance “diamond” trees
    —effectively searching across before up in this specific case. The
    DFLR is otherwise the same; in fact, the MRO is defined by starting
    with the DFLR order and then removing all but the last (rightmost)
    appearances of classes that are visited more than once. This differs
    from DFLR only when there are duplicates, which arise only in diamonds
    that have common superclasses. That said, the built-in object makes
    every multiple-inheritance tree a diamond, so this is a common, if
    implicit, occurrence.
A6 [中文] MRO 在钻石继承中会让较下的子类同名属性优先于较高的共同超类，
    并避免重复访问；可由 DFLR 出发去掉重复中非最后出现者得到。
    因隐含object，很多多重继承树实际都是钻石。

【我的理解与总结】（加深）

【扩展理解】

第 33 章  Exception Basics

【我的理解与总结】（加深）
异常用途：错误处理、终止清理、事件通知；减少遍地手动检查。
未处理 → 传到顶层默认处理（打印回溯并结束）；try/except 可恢复；
    raise/assert 触发；finally/with 保证收尾。

【扩展理解】
• 异常是结构化控制流，优于散落的错误码，但不要当普通分支滥用。
• 捕获应尽量具体，处理完可记录、转换、或继续抛。
• 终止动作：finally 与 with（上下文管理器）保证资源释放。
• 成功路径与错误路径分离，主逻辑更清晰。
• 线程/并发中未捕获异常行为要按模型了解。

【踩坑点】
• 裸 except: 或 except Exception 过宽，吞掉KeyboardInterrupt/编程错误。
• 捕获后 pass：失败静默，线上难查。
• 用异常做热点路径的常规控制（如每循环 expect）：慢且糊。
• 只打印不记录上下文（输入、id、状态）。
• 在库代码里直接 sys.exit 代替抛异常。

第 34 章  Exception Coding Details
     异常编码细节
归属：Part VII 异常与工具 Exceptions and Tools
级别：必读·核心    优先级：高
========================================================================

【我的理解与总结】（加深）
语句职责：try 捕获恢复；except/else/finally 组合；raise 抛出；
    assert调试断言；with 自动化进退场。
把「成功 / 失败 / 清理」三条线写清楚。

【扩展理解】
• try/except/else：else 仅当 try 体无异常时执行。
• finally：无论如何离开 try 都执行（包括 return）。
• 合并 except 与 finally ≈ 外 finally 包内 try/except。
• raise 无参数：把当前异常再抛出。
• assert 条件为假 → AssertionError；python -O 可去掉 assert。
• with 依赖上下文协议 __enter__/__exit__，比手动 finally 更短，
  但只适支持协议的对象。

【踩坑点】
• finally 里 return/压制异常：异常被吞，极难查。
• 用 assert 校验外部输入：-O 后保护消失。
• else 与 finally 混淆（一个是「成功才」、一个是「总是」）。
• with 多个资源顺序与异常打包（Py3 多上下文）不熟。
• raise 链丢失原因：应用 raise X from e。

第 37 章  Unicode and Byte Strings
     Unicode 与字节串
归属：Part VIII 高级主题 Advanced Topics
级别：必读·核心    优先级：高
========================================================================

【我的理解与总结】（加深）
文本/二进制二分：str（Unicode 文本）、bytes（不可变字节）、
    bytearray（可变字节）。
文本模式自动编解码与换行转换；二进制模式原样字节。
    显式encoding是根治乱码的关键。

【扩展理解】
• 跨平台项目：open 文本几乎总应写 encoding='utf-8'（或实际编码）。
• 边界纪律：尽早 decode 成 str，尽晚 encode 成 bytes。
• 源文件默认 UTF-8；可用编码声明；\u/\U 转义。
• ASCII 是许多 Unicode 编码的子集；UTF-8 对 ASCII 兼容。
• BOM 是某些编码的文件头标记；规范化（NFC/NFD）让「看起来一样」
  的字符可比较。
• 不要按固定字节数去切多字节 UTF-8 字符。

【踩坑点】
• str + bytes → TypeError。
• 文本模式读写图片/压缩包：数据损坏。
• 依赖平台默认编码：同一脚本在 Windows/Linux 表现不同。
• 二进制当文本打开又手动编解码，双重处理出错。
• 比较用户输入前未规范化，看起来相等实际不等。

【对你的帮助】
根治乱码。

A3 [中文] 可用 \x、\u、\U 转义写码点；也可在 bytes 里写编码后的字节再 decode；

    str objects in your script, and the contents of binary files are
    represented as bytes (or bytearray) objects. Text-mode files also

Q7 [EN] Why is ASCII text considered to be a kind of Unicode text?
Q7 [中文] 为何 ASCII 也是一种 Unicode 文本？
A7 [EN] ASCII text is considered to be a kind of Unicode text because its

    For example, valid ASCII text is also valid Latin-1 text (Latin-1
    simply assigns the remaining possible values in an 8-bit byte to
    additional characters) and valid UTF-8 text (UTF-8 uses a
    variable-byte scheme for representing more characters, but ASCII
    characters are still represented with the same values in a single
    byte). This makes Unicode backward compatible with ASCII, as long as
    the encodings used represent ASCII the same way.
A7 [中文] ASCII 的 0..127 是许多 Unicode 编码的子集：合法 ASCII也是合法Latin-1、

Q8 [EN] What do BOM and normalization mean in Unicode?
Q8 [中文] BOM 与规范化在 Unicode 中是什么？
A8 [EN] The Unicode BOM is a sequence of bytes added to the front of a text
    string or file in some encodings to both identify the encoding and
    give the string’s endianness. Unicode normalization converts
    characters to a common format to neutralize differences that arise for
    characters that have multiple code-point values in the Unicode
    standard and would fail to match by simple code-point (character)
    equality.
A8 [中文] BOM 是某些编码加在文本/文件开头的字节序列，用于标识编码与字节序。
    规范化把「多重码点表示的同一字符」转到统一形式，
    避免简单按码点比较失败。

【我的理解与总结】（加深）
托管属性：__getattr__（仅当正常查找失败）vs__getattribute__（每次获取
    都进）。
property 是描述符的便捷特例；描述符用类实现 __get__/__set__ 等，更通用。
与装饰器语法结合写校验/计算属性。日常优先 property，框架向再上描述符。

【扩展理解】
• 描述符协议是 property/staticmethod/classmethod 等的底层机制。
• __getattr__ 适合委托、动态属性；property/描述符精确拦截个别名字，
  通常更清晰高效。
• 拦截赋值还需 __setattr__ 或描述符 __set__。
• ORM 字段、校验 setter、懒加载是典型应用。
• dir 与未托管名的表现因机制而异，要实测。

【踩坑点】
• __getattribute__ 里 self.other 再次进入自己 → 无限递归；
  用object.__getattribute__ 或 super。
• 把描述符实例放在实例 __dict__ 而不是类上：协议不生效。
• __getattr__ 与正常属性、属性描述符的查找顺序理解错。
• 用托管属性藏太多副作用，调试变黑盒。
• 与 __slots__ 组合时的限制不清楚。

【对你的帮助】
框架/ORM 向；日常先会 property。

掌握约 50–70% 按目标。

── 第 1 题 ──
Q1 [EN] How do __getattr__ and __getattribute__ differ?
Q1 [中文] __getattr__ 与 __getattribute__ 差别？
A1 [EN] The __getattr__ method is run for explicit fetches of undefined
    attributes only (i.e., those not present on an instance and not
    inherited from any of its classes). By contrast, the __getattribute__
    method is called for every explicit attribute fetch, whether the
    attribute is defined or not. Because of this, code inside a
    __getattr__ can freely fetch other attributes if they are defined,
    whereas __getattribute__ must use special code for all such attribute
    fetches to avoid looping or extra calls (it must route fetches to a
    superclass to skip itself). Neither method is run for implicit fetches
    of built-in operations (sans the next chapter’s heroics).
A1 [中文] __getattr__ 只在「未定义属性」的显式获取失败时调用；
    __getattribute__对每次显式属性获取都会调用（无论是否已定义）。
    因此__getattr__内可较自由取已定义属性；__getattribute__内必须特别小心
    （常经超类取值）以免递归。二者默认都不拦截多数内置运算的隐式获取。

── 第 2 题 ──
Q2 [EN] How do properties and descriptors differ?
Q2 [中文] property 与描述符差别？
A2 [EN] Properties serve a specific role, whereas descriptors are more
    general. Properties define get, set, and delete functions for a
    specific attribute; descriptors provide a class with methods for these
    actions, too, but they provide extra flexibility to support more
    arbitrary actions. In fact, properties are really a simple way to
    create a specific kind of descriptor —one that runs functions on
    attribute accesses. Coding differs too: a property is created with a
    built-in function, and a descriptor is coded with a class; thus,
    descriptors can leverage all the usual OOP features of classes, such
    as inheritance. Moreover, in addition to the instance’s state
    information, descriptors have local state of their own, which can
    sometimes avoid name collisions in the instance.
A2 [中文] property 角色更专一：为某一属性绑定 get/set/delete 函数。
    描述符更通用：用类实现这些动作并可继承、可自带状态，
    避免挤在实例命名空间。实际上 property 是创建特定描述符的简便方式。

── 第 3 题 ──
Q3 [EN] How are properties and decorators related?
Q3 [中文] property 与装饰器关系？
A3 [EN] Properties can be coded with decorator syntax. Because the property
    built-in accepts a single function argument and returns a function, it
    can be used directly as a function decorator to define a fetch-access
    property. Due to the name rebinding behavior of decorators, the name
    of the decorated function is assigned to a property whose get accessor
    is set to the original function decorated ( ```python
    name=property(name) ``` ). Property setter and deleter attributes
    allow us to further add set and delete accessors with decoration
    syntax—they set the accessor to the decorated function and return the
    augmented property. Some may find this a bit clumsy, but this is
    subjective.
A3 [中文] property 可用装饰器语法：@property 把方法变成取值访问器；
    .setter/.deleter 再装饰添加写/删。名字重绑定使原函数名变成property对象。

── 第 4 题 ──
Q4 [EN] What are the main functional differences between __getattr__ and
    __getattribute__ and properties and descriptors?
Q4 [中文] __getattr__/__getattribute__ 与 property/描述符主要功能差别？
A4 [EN] The __getattr__ and __getattribute__ methods are more generic: they
    can be used to catch arbitrarily many attributes. In contrast, each
    property or descriptor provides access interception for only one
    specific attribute—we can’t catch every attribute fetch with a single
    property or descriptor. On the other hand, properties and descriptors
    handle both attribute fetch and assignment by design: __getattr__ and
    __getattribute__ handle fetches only; to intercept assignments as
    well, __setattr__ must also be coded. The implementation is also
    different: __getattr__ and __getattribute__ are operatoroverloading
    methods, whereas properties and descriptors are objects manually
    assigned to class attributes. Unlike the others, properties and
    descriptors can also sometimes avoid extra calls on assignment to
    unmanaged names and show up in dir results automatically, but are also
    narrower in scope—they can’t address generic delegation goals. In
    Python evolution, new features tend to offer alternatives but often do
    not fully subsume what came before.
A4 [中文] __getattr__/__getattribute__ 更泛：可一次拦截大量名字；
    每个property/描述符通常只接管一个具体属性。后两者天然覆盖读和写；
    前两者主要管读，写还需 __setattr__。实现上前两者是运算符重载方法，
    后两者是赋在类上的对象。各有擅长，新特性往往是替代方案而非完全取代。

【我的理解与总结】（加深）
元类：创建「类」的类；声明 class C(metaclass=M)。
类装饰器与元类都能在 class 语句结束时介入；元类更深（参与构建过程、
    影响继承体系）。
多数业务优先普通类与装饰器；读框架时再深挖。

【扩展理解】
• 默认类是 type 的实例；元类常子类化 type，
  重写__new__/__init__/__call__。
• type(name, bases, dict) 可动态造类。
• 用途：ORM 模型声明、API 自动注册、抽象检查、接口强制。
• 元类上的方法是给「类对象」用的，不会自动变成其实例的方法。
• 能装饰器解决的，别先上元类。

【踩坑点】
• 两基类带来冲突元类：合并失败 TypeError。
• 元编程过度：工具支持差、新人读不懂、错误信息难解。
• 元类与类装饰器叠床架屋，顺序难推理。
• 在业务代码炫技使用元类，review 成本高。
• 忽略 type 与 object 在继承树上的位置。

【对你的帮助】
理解框架底层；多数业务不必手写。

【建议掌握程度】
掌握约 40–60% 了解级。

【章节测验 · 中英对照】

── 第 1 题 ──
Q1 [EN] What is a metaclass?
Q1 [中文] 什么是元类？
A1 [EN] A metaclass is a class used to create a class. Classes are instances
    of the type class by default. Metaclasses are usually subclasses of
    the type class, which customize classes. They may redefine
    class-creation protocol methods like __new__ and __init__ to customize
    the class creation call issued at the end of a class statement. They
    may also define data and methods that provide behavior for their
    instance classes, but these are inherited only by classes, not their
    nonclass instances. Metaclasses can also be coded in other ways—as
    simple functions, for example—but they are responsible for making and
    returning an object for the new class. Finally, metaclasses constitute
    a secondary pathway for inheritance search used for classes alone;
    this allows classes to ape normal instance behavior, though it
    bifurcates the class story for relatively rare and narrow roles.
A1 [中文] 元类是用来创建类的类。默认情况下类是 type 的实例；
    元类通常是type的子类，通过重写 __new__/__init__等定制class语句结束时的
    类创建过程。也可为「类」提供行为，但一般只被类继承，不被普通实例继承。
    元类也可用函数等形式实现，但须负责创建并返回类对象。

── 第 2 题 ──
Q2 [EN] How do you declare the metaclass of a class?
Q2 [中文] 如何声明类的元类？
A2 [EN] Use a keyword argument in the class header line: class C (metaclass= M
    ```python ) ``` . The class header line can also name normal
    superclasses before the metaclass keyword argument; these superclasses
    are searched before metaclasses for inheritance run from a class.
A2 [中文] 在 class 头用关键字参数：class C(Super, metaclass=M): ...。
    普通超类写在前面；从类出发的继承查找先找超类再涉及元类路径。

── 第 3 题 ──
Q3 [EN] How do class decorators overlap with metaclasses for managing classes?
Q3 [中文] 类装饰器与元类在“管理类”上如何重叠？
A3 [EN] Because both are automatically triggered at the end of a class
    statement, class decorators and metaclasses can both be used to manage
    classes. Decorators rebind a class name to a callable’s result, and
    metaclasses route class creation through a callable, but both hooks
    can be used for similar purposes. To manage classes, decorators simply
    augment and return the original class objects. Metaclasses augment a
    class after or before they create it. As noted, metaclasses can also
    provide behavior for their instance classes in the form of methods
    that are not immediately supported by decorators, though the objects
    returned by decorators can do anything supported by the Python
    language.
A3 [中文] 二者都会在 class 语句结束时自动触发，都可用于管理类。
    装饰器把类名重绑到可调用的返回值；元类把类创建路由到可调用。
    管理类时装饰器常增强并返回原类；元类在创建前后增强。许多任务二者皆可，
    优先更简单的装饰器；元类更深但更重。
